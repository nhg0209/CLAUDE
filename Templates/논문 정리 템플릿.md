## 1. 문제 정의

### 무엇을 풀려고 하는가

### 기존 방법이 어디서 깨지는가

**구체적인 지형과 조건으로** 쓴다. "성능이 낮다"가 아니라
"높은 풀을 기하학적 장애물로 오분류해서 멈춘다"처럼.

> [!tip] 오프로드 특유의 실패 모드 체크리스트
> - 비기하학적 장애물 (풀·수풀은 밟아도 되는데 높이로는 바위와 구분이 안 됨)
> - 같은 semantic class인데 traction이 다름 (마른 흙 vs 젖은 흙)
> - 시야 밖·가려짐 (수풀 뒤의 도랑)
> - slip / sinkage로 명령과 실제 궤적이 벌어짐
> - 지형이 학습 분포 밖 (out-of-distribution)

## 3. ★ Supervision — 무엇이 라벨인가

**이 분야 논문을 가르는 축.** 네트워크 구조보다 여기가 기여인 경우가 대부분이다.

| 항목 | 내용 |
|---|---|
| 라벨의 출처 | 사람 annotation / 주행 결과(hindsight) / proprioception / 시뮬 ground truth |
| 라벨이 붙는 대상 | 픽셀 / BEV cell / 궤적 / 스칼라 cost |
| 라벨 생성 지연 | 즉시 / 지나간 뒤에야(hindsight) / 온라인 적응 |
| 이 방식이 못 하는 것 | |

> [!question] 이 supervision이 실제로 측정하는 것은 무엇인가
> "traversable"이라는 라벨이 실제로는 *"이 로봇이 이 속도로 지나갔을 때 진동이 작았다"*
> 를 뜻하는 경우가 많다. **플랫폼과 속도에 종속**된다는 뜻이다.
